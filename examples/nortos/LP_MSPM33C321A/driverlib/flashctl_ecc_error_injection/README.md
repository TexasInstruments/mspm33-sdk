## Example Summary

This example demonstrates testing ECC logic by writing invalid data to inject SEC (single bit error correction) and DED (double bit error detection) errors.

First a single flash word is correctly programmed with the ECC code generated by the flash controller hardware. The ECC code that was generated for this flash word is read back from the ECC code space.

Then a SEC error is demonstrated by programming a flash word with ECC that has a one bit difference from the data that corresponds with the ECC code. A SEC error will be reported by SYSCTL, and since SEC errors are correctable, the "corrected" code will be programmed to the corrected code space.

Last, a DED error is demonstrated by programming a flash word with ECC that has a two bit difference from the data that corresponds with the ECC code. A DED error will be reported by SYSCTL, and a DED error will also result in an NMI (Non-Maskable Interrupt) triggering with a DED fault. DED errors are uncorrectable, so the flash word will be programmed to the corrected code space.

## Example Usage

Compile, load and run the example.
The flash operations will start automatically when the example is run.
The application will stop at different SW breakpoints so the user can verify the data and status match the expected values in the comments. The final breakpoint is placed in the NMI_Handler, since the injected DED error will trigger an NMI fault.
LED2 Green (PASS_LED) will turn on after all operations are completed successfully.

## Application Design Details

This example demonstrates the following FlashCTL operations related to ECC error injection:

1. Programming 128-bit data with hardware-generated ECC using DL_FlashCTL_programMemoryFromRAM128WithECCGenerated
2. Reading back the ECC code that was generated for the data
3. Enabling manual ECC code override using DL_FlashCTL_enableOverrideHardwareGeneratedECC
4. Injecting a Single-bit Error Correction (SEC) error:
   - Programming data with a single bit difference from the original data
   - Using the ECC code from the original data
   - Verifying that a SEC error is reported by SYSCTL
   - Confirming that the corrected data matches the original data
5. Injecting a Double-bit Error Detection (DED) error:
   - Programming data with a two-bit difference from the original data
   - Using the ECC code from the original data
   - Triggering an NMI with a DED fault
   - Handling the NMI in the NMI_Handler

The example uses the following FlashCTL APIs from dl_flashctl.h:
- DL_FlashCTL_unprotectSector: Unprotects a sector for erase/program operations
- DL_FlashCTL_eraseMemoryFromRAM: Erases a sector of memory
- DL_FlashCTL_programMemoryFromRAM128WithECCGenerated: Programs 128-bit data with hardware-generated ECC
- DL_FlashCTL_enableOverrideHardwareGeneratedECC: Enables manual ECC code override
- DL_FlashCTL_programMemoryFromRAM128WithECCManual: Programs 128-bit data with user-provided ECC

The example also uses SYSCTL APIs to manage ECC errors:
- DL_SYSCTL_clearECCErrorStatus: Clears ECC error status
- DL_SYSCTL_getStatus: Gets the current SYSCTL status
- DL_SYSCTL_getPendingNonMaskableInterrupt: Gets the pending NMI source

This example demonstrates how the ECC mechanism in the flash controller works to detect and correct errors, which is important for ensuring data integrity in critical applications.
