MSPM33 客户安全代码和引导加载程序 (CSC) 用户指南
================================================

1. 简介
-------

客户安全代码 (CSC) 是为具有高级安全功能的 MSP 系列设备（如 MSPM33 设备系列）实现的公开可用的 mcuboot，允许客户在其开发和部署中拥有额外的更高级的安全引导功能。当与此示例等应用程序镜像配对时，这代表了设备上更新和验证新镜像的完整解决方案。然而，客户安全代码的严格定义仅指镜像验证和配置安全设置，而不是将镜像加载到设备上。完整的功能集和执行流程将根据所使用的特定设备和设备上存在的功能而有所不同。

严格定义的客户安全代码具有以下功能：

-  它可以使用椭圆曲线数字签名算法 (ECDSA) 与 NIST P-256 曲线和哈希算法 SHA-256 验证一个或多个应用程序镜像

-  它可以使用 ML-DSA 87 和哈希算法 SHA-256 验证一个或多个应用程序镜像

-  mcuboot 是开源的，可以修改以适应最终开发人员的需求，此外，CSC 有自己的一套安全功能，可以通过头文件或 SysConfig 轻松配置，以根据用户的最终需求定制解决方案

-  它使用全局安全控制器在设备上设置安全功能，如写保护、读保护和 IP 保护

-  它可以提供回滚保护

-  它可以被设为不可变并在引导过程中作为信任根 (RoT) 链的一部分

-  通过 SysConfig 工具提供简单的功能配置，使用户可以快速构建适合其需求的 CSC

当前 CSC（严格定义）不做的一些事情：

-  它不会将应用程序镜像加载到设备上（不替代引导加载程序）

-  它不保证在设备上完全实现安全引导

**注意：目前一些功能仍在开发中，因此请联系 TI 咨询任何问题和额外需求的优先级**

2. 使用示例
-----------

建议运行现有的 ``customer_secure_code`` 和 ``customer_secure_code_sample_image`` 示例对，以便在进一步开发之前更好地理解每个组件的开发流程。提供的示例具有测试密钥和几个预构建的镜像，可以让开发人员熟悉成功运行和验证示例。这两个项目都应导入到兼容的 CCS 版本中。此示例使用 MSPM33 LaunchPad，设置如项目 README 所示。

2.0 先决条件
~~~~~~~~~~~~

要运行初始设置，请确保安装了 Python 3.11 或更新版本以及最新的 pip 包，并运行以下命令下载必要的要求。

::

    python -m pip install --user -r source/third_party/mcuboot/scripts/requirements.txt
    pip install dilithium_py

2.0.1 OSX 或 Linux 中的 Python 版本控制
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

函数和预构建步骤将使用带有命令 ``python`` 的 Python 3.11 来调用 python 可执行文件。因此，命令 ``python --version`` 应该显示 3.11 或更高版本。

在 Linux 或 Mac 设置中，python 可能指的是不同的版本，因此建议将 ``python3`` 命令别名为 ``python``\ ，或者如果需要两个不同的版本，则修改示例中的后期构建步骤以使用 ``python3`` 代替。

2.1 应用程序镜像示例构建
~~~~~~~~~~~~~~~~~~~~~~~~

应用程序镜像示例 ``customer_secure_sample_image`` 是一个 CCS 项目，包含将 LED 引脚设置为蓝色的配置。此应用程序镜像设计为就地执行。

**注意：没有引导应用程序，应用程序镜像无法在设备上单独运行。**

为了切换配置，可以导航到项目的\ **属性**\ 并选择\ **管理配置**\ 来设置活动配置，或使用\ **全部构建**\ 同时构建两种配置。

建议同时构建两种配置，以便能够测试引导应用程序的更多功能。

此过程还包括一个后期构建步骤，可以在\ **属性 → 构建**\ 的\ **步骤**\ 选项卡中找到。这负责签名镜像并将其输出为二进制文件和 ti-txt 文件，其中包含有关它的重要信息。

构建的镜像二进制名称的元素如下：

-  编译地址：镜像编译执行的地址，它应该被加载到编译地址或（bank 偏移量）+编译地址。

-  版本：镜像的版本

2.2 运行引导示例
~~~~~~~~~~~~~~~~

构建两个示例。在刷写设备之前，转到\ **属性 → 调试**\ ，并从调试页面左侧的列表中选择 MSPM33 Flash 设置。然后将擦除方法配置为擦除主存储器和非主存储器（如下所示），并将重置类型配置为硬重置（如果可用）。

.. figure:: ./images/main_nonmain_erase.png
   :alt: 

之后，开始调试项目。现在应该进入主函数。现在设备上不应该有任何有效的镜像，因此运行示例应该会导致红色 LED 闪烁。

2.3 加载二进制镜像
~~~~~~~~~~~~~~~~~~

要将二进制镜像加载到设备上，请在调试引导应用程序时按照以下步骤操作：

1. 在刷写 CSC 镜像之前，确保将擦除配置设置为不擦除 Flash 存储器。

   .. figure:: ./images/donot_erase_flash.png
      :alt: 

2. 打开设备的内存浏览器，可以通过导航到\ **查看 → 内存浏览器**\ 找到。要加载二进制镜像，暂停设备运行，选择\ **加载内存**

   |image0| |image1|

3. 指向在\ `构建应用程序镜像 <#应用程序镜像示例构建>`__\ 中构建的特定示例镜像。建议在按照签名步骤后加载镜像。首先参考有关如何签名示例应用程序镜像的分步说明部分。生成签名镜像后，通过加载内存加载它。从下拉列表中选择二进制文件类型，如下所示。点击底部的\ **下一步**\ 。

4. 最后，输入起始地址。这应该与第一个内存槽的值以及文件名中列出的值匹配。写入后，选择\ **完成**\ 。

5. 通过检查内存浏览器中的早期闪存内存（如 0x0000）来验证引导应用程序尚未被擦除。还要验证镜像已成功加载到镜像槽中，方法是在内存浏览器中输入起始地址。如果两个元素都存在，则可以使用 LaunchPad 上的重置按钮重置设备。这将发出比调试器 SYSRST 更强的 BOOTRST 并执行安全策略。在引导过程中，红色 LED 将在执行引导例程时保持常亮。无论在哪个 bank，正确签名的最高版本镜像都应该运行。LED 应该从红色转变为绿色或蓝色 LED（取决于运行的镜像）。

3 使用客户安全代码进行开发
--------------------------

虽然示例为一些开发技术提供了良好的起点，但本节详细说明了一些可能需要的开发，以便充分利用 CSC。

3.1 创建和使用密钥
~~~~~~~~~~~~~~~~~~

ECDSA 和 MLDSA 目前是 CSC 支持的认证方法。 公钥将存储在设备闪存中，私钥将由开发人员安全维护。 mcuboot 文件夹中包含 imgtool.py python 脚本，可以签名镜像和创建密钥。

为了生成新密钥，用户可以输入以下命令创建一个名为 newkey.pem 的密钥（或任何合适的名称）：

\`\`\` cd source/third\_party/mcuboot/

ECDSA 密钥生成
==============

scripts/imgtool.py keygen -k newkey.pem
